A Nomenclature for Juicebox Web

The words in CONTEXT.md, each placed on the thing it names — first on one browser, then on the two ways several browsers relate.

Written 2026-09-13 · every definition is quoted from CONTEXT.md, which remains the authority

Reading this page

Every term below is defined in this repository’s CONTEXT.md. This page adds nothing to it; it only points. Where the glossary lists words to avoid, they are repeated here, because most confusion arrives through a synonym rather than through the term itself.

The vocabulary arrives in three figures, each showing only what its words need. The first is a single browser in its shell, drawn in full. The second and third reduce browsers to outlines, to show the two ways several browsers relate: syncing, and aiming.

This vocabulary is juicebox-web’s. The library it wraps, juicebox.js, keeps a glossary of its own, and the two do not always agree — where they collide, the collision is noted rather than smoothed over.

One browser, in its shell

Start with the simplest arrangement the application has: one contact map, open in one browser. Nearly every word in the glossary can be pointed at on this one screen.

1

Shell

The parts of the page this repo owns: menus, modals, widgets, and the catalogs behind them. Distinct from the viewer it surrounds.

Avoid: chrome, wrapper, frontend
2

Viewer

The juicebox.js library instance that draws contact maps and tracks. Everything it renders is the library’s responsibility, not this repo’s.

Avoid: juicebox, the app, hic
3

Browser

A single viewer panel with its own loaded map, tracks, and locus. Several can be open at once.

Avoid: panel, instance, window
4

Clone

The control that opens another browser. One viewer, several browsers.

5

Widget

A shell-owned interface element for getting data into the viewer. The panel’s own controls are the viewer’s, and are not widgets.

Avoid: component, control
6

Contact map

A Hi-C dataset (a .hic file) giving contact frequency between every pair of genomic loci in a genome. The primary thing a user loads.

Avoid: heatmap, matrix, hic file, dataset
7

Control map

A second contact map loaded alongside the first for comparison. The interface calls the pair “A” and “B”; the control map is B.

Avoid: B map, comparison map, secondary map
8

Resolution

The bin size at which a contact map is displayed. Changing it changes counts per bin, so the color scale must change with it.

Avoid: zoom level, granularity
9

Track menu

The genome-keyed catalog of curated tracks and 2D annotations offered for the currently loaded genome.

Avoid: annotation datalist, track list
10

Track

A one-dimensional annotation displayed along a map axis, positioned by a single genomic interval.

Avoid: 1D track, signal, feature track
11

2D annotation

An annotation positioned by a pair of intervals, so it draws on the face of the map rather than along an axis. Loops and domains are 2D annotations.

Avoid: 2D track, feature pair, overlay
12

Genome-derived track

A track that comes from the genome definition rather than a catalog: the reference sequence and its gene annotation. There are exactly two, one per toggle — a checkbox in the track menu which, unlike every other load surface, both loads and unloads.

Avoid: built-in track, default track; for the toggle, switch, button, control
13

Session

The complete restorable state of the shell and its viewers: maps loaded, tracks loaded, loci, color scales. Saved to and loaded from a JSON file.

Avoid: state, workspace, config
14

Share URL

A session compressed into a link, shortened for distribution and also offered as a QR code. Opening one restores the session it encodes.

Avoid: permalink, session link, short URL
15

Caption

Shell-owned editable text beneath the stage. Outside the viewer’s DOM, and therefore this repo’s to draw.

Browsers that sync

Open a second browser and the first new idea appears. Nothing about a single browser needs repeating to show it, so the browsers here are reduced to what syncing touches: which genome each map belongs to, and which locus each is showing.

16

Sync group

The browsers whose locus follows one another’s. Membership is derived, not chosen: the library pairs two browsers when their maps are the same assembly and carry the same chromosomes. Settled when a map loads, and unchanged as the user pans.

Avoid: linked panels, locked panels, target set
17

Sync refusal

A browser belonging to no sync group while other browsers are open, because its map is a different assembly, lacks chromosomes the others carry, or was opted out by the host. Marked on the panel, by the viewer. A browser that is merely the only one open has not been refused — there is nothing to sync with.

Avoid: sync error, unsynced, sync failure

Aiming at several browsers

The second idea is about where a load lands. The same three browsers are shown, reduced further still: the maps no longer matter, only the borders that mark who is chosen, and the track that arrives.

18

Current browser

The browser the shell’s menus read: the one whose genome, map and size they interrogate to decide what to offer. Exactly one whenever any browser exists, and shown by its border. It is what a menu is about, which is no longer the same as what a load reaches.

Avoid: selected browser, active browser, focused browser
19

Target set

The browsers a track load reaches: the current browser, plus any others the user has aimed at. Shown by the dashed blue outline. Owned by juicebox.js — the shell asks for the set, it does not maintain one.

Avoid: multi-select, selection, selected browsers, sync group
20

Aim

The act of choosing a target set, and the state of having chosen one. Shift-click a browser’s navbar to aim; a plain click clears the aim.

Avoid: multi-selecting, targeting

Two groupings, and why they are not one

Figures 2 and 3 show two different groupings of browsers, and they are the pair most often confused for each other. A target set is what a track load reaches: the user picks it by shift-clicking, and it is drawn as the dashed blue outline. A sync group is what a locus change reaches: nobody picks it, the library derives it from whether two maps are the same assembly carrying the same chromosomes, and it has no outline at all.

Neither implies the other. Two browsers can sync without being aimed at together, and two browsers can be aimed at together while one of them cannot sync with anything. Browser C sits outside both — outside the sync group in Figure 2, outside the target set in Figure 3 — but for unrelated reasons, and fixing one would not fix the other.

Aiming at a browser does not make it follow. No amount of shift-clicking will sync a dm6 map to an hg38 one.

The glossary keeps both terms and lists each under the other’s avoid line, which is the only place in this repository’s vocabulary where two live terms are mutually excluded. That is deliberate: the error worth guarding against is not using the wrong word, it is believing there is only one thing to name.

Where the shell stops

The distinction between shell and viewer is not a figure of speech. It is a line in the DOM. js/app.js calls hic.init(container, config) on #app-container; from that call onward, everything inside that element belongs to the library. The shell owns what surrounds it.

This is why a question like “can we put a badge on the panel?” has an answer before it has a design: not from this repository, it cannot. The panel, its navbar, its borders and its locus box are all drawn by juicebox.js. A shell-owned notice must either live outside the stage, or the library must grow the surface itself.

If you would change it by editing this repository, it is the shell. If you would change it by opening a pull request against juicebox.js, it is the viewer.

Not pictured

Six terms name things a screenshot cannot show — they are either behind a modal, or chosen at build time.

TermMeaning
Map menu The curated, searchable catalog of published contact maps offered in the load menu, each entry carrying its publication, organism, cell type, and protocol. Avoid: map list, file list, hicfiles
Datasource An adapter that turns one external catalog — the curated map menu, ENCODE-hosted maps, 4DN maps — into rows of a searchable table. One per catalog; they differ in columns and in how they are queried. Avoid: provider, backend, source, repository
Distribution A build of the shell for a particular deployment — the default one and the AidenLab one, which differ in branding and entry page. Selected by build mode, not at runtime. Avoid: flavor, variant, target, environment
Embed A page that hosts a bare viewer with no shell — no menus, no catalogs — for placing a map inside someone else’s page. Avoid: iframe, widget mode
Genome The reference assembly a contact map is aligned to, named by its identifier (hg19, mm10). It is the key to nearly every catalog in the shell: switching genomes re-derives the track menus. Avoid: assembly, reference, build
Track registry The mapping from genome to the ENCODE track catalogs available for it. Determines which ENCODE load options a genome offers at all. Avoid: track index, catalog
